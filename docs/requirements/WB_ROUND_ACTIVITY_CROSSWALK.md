## ผลต่อพฤติกรรม

- ledger ที่เขียนตอนบันทึกผลระดับ Program ใช้ `roundActivitySourceFor`: ตารางกิจวัตรและการ์ดความฝันที่บันทึกในครั้งที่ 1 เป็น **PLANNED** สำหรับแถวใหม่.
- แถวที่ derive ตอนอ่าน (ไม่มี ledger) ใช้ catalog เดียวกัน: Goal Plan ครั้งที่ 2 และแผนที่ปรับใน Follow-up ของครั้งที่ 4 เป็น PLANNED (แผนที่ปรับในครั้งหลังไม่ทำให้ครั้งที่ 4 เป็น DONE); "ทบทวนแผนสุขภาพ" ครั้งที่ 3–6 เป็น DONE (mode REVIEWED) เมื่อ Follow-up ของครั้งนั้นมี `sourceGoalPlanId` และตอบ `planAdjusted` แล้ว (D5) — แถว ledger ถ้ามียังมาก่อน; ถ้าไม่เข้าเงื่อนไขแสดงเหตุผล (`followupEvidence.goalPlanLinked` / `planAdjustedAnswered`).
- `decisionGated` ถูกถอดออก เพราะทุกกล่องที่เคยรอ decision มีขั้นตอนที่อนุมัติแล้ว.
- ครั้งที่ 3–6 แสดง "รายการที่ต้องติดตามในครั้งนี้" = กิจกรรมในแผนที่ยังไม่ถึงเป้า (`planFollowUp.dueItems`) + รายการของครั้งนั้น; ที่ถึงเป้าแสดงแยก "ทำได้ตามเป้าแล้ว" (`metItems`) (D6). Add เหมือนเดิม.
- `HEALTH_PATH` ยังเป็น "รอแบบฟอร์มจากหน่วยงาน" ไม่เคยเป็น DONE และทบทวนไม่ได้. การทบทวน (WB-DF-03) ไม่เขียนผลเดิมทับ.
- ไม่เปลี่ยน Goal Plan, Follow-up, เลขรอบ (ครั้งที่ N = Follow-up N−2) หรือสูตรคะแนน; migration ของ Phase D (`20261021100000_cvd_risk_score`) ไม่แตะ ledger หรือ enum.

## Historical data

- แถว `PatientProgramRoundActivity` ที่บันทึกแล้วเก็บ `source` ณ เวลานั้นและ **ไม่ถูกเขียนใหม่** (ไม่มี backfill): แถวเดิมของ `ROUTINE`/`DREAM_CARD` ครั้งที่ 1 ที่บันทึกเป็น EXTRA ช่วง A-01 จึงคงเป็น EXTRA ส่วนแถวใหม่เป็น PLANNED — มี 2 ค่าในประวัติชุดเดียวกันได้. ถ้าต้องการแปลงต้องมี remediation rule ที่อนุมัติแยก.
- **`KNOW_SELF` / `LIFE_TABLE`:** enum ใน Postgres คงไว้. ไม่มีเส้นทางเขียนแถวด้วยรหัสนี้ในแอป (การทบทวนรับเฉพาะ `REVIEWABLE_TOOL_CODES` และ ledger ของ Service 1/แบบประเมินเขียนเฉพาะรหัสของตน); ตรวจ integration DB หลัง `prisma:migrate:test` (2026-10-16): 0 แถวที่ใช้รหัสนี้ (ฐานทดสอบไม่มีแถว ledger เลย). ไม่ได้ตรวจฐานข้อมูล Supabase/production ในงานนี้. ถ้าพบแถวในภายหลัง read model จะไม่แสดงแถวนั้น (ถูกกรองจากทุกรายการ) — ต้องหยุดและตัดสิน remediation ก่อน ไม่เขียนประวัติใหม่.
- การจัดประเภทที่ derive ตอนอ่านเป็นการแสดงผลจาก catalog ปัจจุบัน ไม่ใช่เหตุการณ์ที่ persist. ไม่มี report ที่อ่าน `source` ของ ledger.
