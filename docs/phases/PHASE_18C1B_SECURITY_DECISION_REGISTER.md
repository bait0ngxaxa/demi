## Approval evidence format

เพื่อให้ตรวจย้อนหลังได้ การปิด decision ใดในอนาคตต้องบันทึกผู้มีอำนาจตาม role, วันที่, exact decision wording, scope/capability/field set/version, evidence ที่ review, conditions/expiry, objections/unresolved dependency และผลต่อ safe fallback. ห้าม update เป็น ACCEPTED จากคำแนะนำในตาราง, requester confirmation ของ product requirement, merge/commit, automated synthetic pass หรือการอ้างเอกสารอย่างเดียว

การอนุมัติ Patient detail ต้องแยกจาก Global overview และ per-Hospital summary. Data Controller/Privacy approval เป็น gate เพิ่มเติมสำหรับการประมวลผล/เปิดเผยข้อมูล identifiable/health ตาม governance จริง ไม่ถูกแทนด้วย Product Owner หรือ engineering. Clinical authority ต้องอนุมัติ clinical meaning/formula/field เมื่อเกี่ยวข้อง. Security/Architecture acceptance และ implementation authorization เป็นคนละขั้น

## Decision identity และ cross-contract rules

- GR-REQ-01 เป็น product requirement reference เท่านั้น; ใช้ trace ว่าคำขอ Platform Global dashboard และ Patient drill-down ได้รับการยืนยัน
- GR-REQ-01 ยืนยันว่า Global Admin คือ Platform/System administrator ที่ใช้ Role.ADMIN; GR-SEC-01 ตัดสิน current-state prerequisite และ grant เพิ่มเติม ไม่เปิด role identity ที่ยืนยันแล้วใหม่
- GR-SEC-01 ถึง GR-SEC-19 เป็นข้อเสนอ security namespace สำหรับ Global Reporting โดยเฉพาะ; ทั้งหมดยัง OPEN
- R24A-D01–D15 คง PROPOSED FOR REQUESTER / CUSTOMER REVIEW; ไม่มีการสร้าง D16
- RPT-24/RPT-24C exact-Hospital Excel export gates คง OPEN
- HN-M07 และ historical reparent disclosure คง OPEN; HN-M08 คง DEFERRED / NOT AUTHORIZED
- Global on-screen reporting, exact-Hospital Excel export และ Hospital Network aggregate เป็นคนละ actor/scope/operation contract
