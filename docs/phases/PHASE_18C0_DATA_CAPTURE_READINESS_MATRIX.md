## 4. Minimal future data-capture decisions that unblock trusted outcomes

The smallest defensible work is decision-gated; each item may resolve through a confirmed existing source rather than a new field.

1. **Stage and event time (CF18-08/11; G18-03/09; D06/D07):** decide which dated source represents each stage and whether a verified encounter/measurement date must be captured. Keep Program lifecycle time, record time and patient event time distinct.
2. **Achievement fact (CF18-10/11; G18-04; D06/D09/D10/D12):** choose the observation method and owner, exact PatientProgram/GoalPlan/Follow-up linkage, period and eligible activity units. Only then decide whether an actual-days input is required and approve the rate/70% calculation. Do not create a field or formula yet.
3. **Structured Follow-up facts (CF18-11; G18-05; D10/D12):** decide if controlled outcome, adjustment decision/application, and obstacle flag are required. If yes, define vocabulary/state, actor, timestamp, linkage and correction history separately.
4. **Clinical field gaps (CF18-08/11; G18-03; D06–D09/D12):** select authoritative sources for HbA1c After, BMI stage pair, CVD risk, illness onset/duration and PAM/PROMs before considering new capture or derivation.
5. **Classification and denominator (CF18-17; G18-07; D01/D03/D08/D14):** approve clinical vocabulary, effective time and whether counts represent Person, relationship or Program; keep exact-Hospital boundary.
6. **OSM responsibility (CF18-06/17; G18-08; D05):** decide whether the requested workbook field is current assignment, historical assigned responsibility, recorder or care deliverer; require provenance only for the chosen meaning.
7. **Projection and presentation (CF18-17; G18-01/02/09/10; D01–D04/D07/D11–D15):** after field meaning is approved, decide allowlisted projection, missing/zero/unknown/NA handling, Follow-up overflow and stable workbook representation.

### 4.1 Existing create/correction constraints to review after decisions

- PatientBaseline is unique per PatientHospitalRelationship, not one per Program. A correction/replacement and its history are not authorized by this package.
- GoalPlan creation records rounds and audit provenance, but schema has no explicit supersedes/effective-date relationship. A new round is not, by itself, a Follow-up adjustment event.
- Follow-up create operations assign recordedAt from application time and persist an optional sourceGoalPlanId; no encounter timestamp is supplied by this operation. Numeric clinical units and correction/history semantics remain open.
- Final Assessment is optional and unique per Program; model fields do not include HbA1c, height or BMI. Program completion is a separate status operation.
- PatientClassification has a history model, but changedAt is not a clinical effective date and no Program-level snapshot is present.
- PersonalExerciseEntry supports Patient SELF update/delete with updatedAt, but that audit time does not create a Program-care relationship or clinician validation.
