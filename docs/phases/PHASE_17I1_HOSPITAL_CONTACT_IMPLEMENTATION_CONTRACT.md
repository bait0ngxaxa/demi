## 3. Persistence selected for later implementation

Select dedicated Prisma model/table **`HospitalContact`**, with default unmapped table/column names matching repository conventions. Hospital relation **`contact HospitalContact?`**; inverse Contact relation **`hospital`**. Hospital 1 → Contact 0..1.

| Field | Exact planned representation |
| --- | --- |
| `id` | UUID PK, generated server-side using repository UUID convention; immutable |
| `hospitalId` | UUID NOT NULL, UNIQUE; FK → Hospital.id, `onDelete: Restrict`, `onUpdate: Cascade` explicitly |
| `addressText` | nullable String / VarChar(500) |
| `phoneNumber` | nullable String / VarChar(32) |
| `createdAt` | DateTime / timestamp(3), default now; server explicitly sets millisecond instant on create |
| `updatedAt` | DateTime / timestamp(3), @updatedAt convention; service explicitly sets monotonic millisecond version on state-changing writes |

The unique hospitalId constraint enforces exactly at most one row per Hospital and indexes the FK; no additional redundant hospitalId index. FK Restrict avoids destroying operational data by identity deletion; no Hospital delete operation is added. These are future schema instructions, not schema edits now. No editor/source/trust/status/soft-delete/revision fields or generic settings table.

No row means never materialized contact and both values absent. A row with both nullable fields null is **legal** and means cleared current contact with a surviving version. Absence and an empty row give the same Patient no-data projection but distinct editor concurrency tokens. Retain row after clearing both fields; no physical Contact delete operation. This prevents absence→create→clear→absence ABA retries. First empty desired state against absence is NOOP and does not materialize a row. First nonempty state creates; subsequent desired-state submissions update/clear the same row.

This separation preserves Q99: Master identity maintenance cannot own, reset or synthesize operational contact. Existing Hospitals with zero contact remain valid. Forward-only migration creates the empty table/constraints and optional relation; **no backfill, fake values, legacy extraction or Master-derived values**. Hospital Master seed remains idempotent and must neither create nor update/delete HospitalContact, including nested writes. Clean empty database migration path and seed coexistence must be tested later; no migration runs now.

## 4. Exact field and input contract

Transport validates a bounded request; service validates a strict schema derived from one contact-owned schema/normalizer. Canonical application mutation object contains exactly `hospitalId`, `expectedUpdatedAt`, `addressText`, `phoneNumber`. UUID locator; expectation null or canonical UTC ISO millisecond timestamp. Both contact keys are required in a full desired-state submission, with **string or null** values; missing/undefined, numbers, arrays, objects and extra keys are invalid. Optional product fields mean nullable values, not patch omission. Transport converts empty form strings through the same normalizer; it does not coerce numeric phones.

Technical bounds follow existing VarChar evidence, without importing Patient domain validation. Length is normalized JavaScript UTF-16 code units, matching conventional string validation and conservatively fitting PostgreSQL character limits. Reject unpaired surrogates. No truncation, Unicode normalization, translation, country-code inference or inferred values. Preserve Thai spelling/combining marks exactly. At the transport boundary, bound the combined **unnormalized contact-field payload to 16 KiB UTF-8** before expensive domain processing; oversized input receives sanitized validation error, not silent truncation. The framework's existing overall action request-body limit remains in force; no unrelated global configuration change is required.

| Field | Canonical normalization and allowed structure |
| --- | --- |
| `addressText` | Null stays null. Convert CRLF and CR to LF; convert TAB to one U+0020 space. Apply ECMAScript trim to whole string edges; remove trailing U+0020 spaces on each line, then trim edges again. Blank becomes null. Preserve interior LF, leading indentation on interior lines, repeated interior spaces and empty lines; do not collapse words/lines. Maximum 500 UTF-16 units after normalization. Reject remaining C0 controls except LF, DEL/C1 (U+007F–U+009F), U+200B/U+200E/U+200F, U+202A–U+202E, U+2060/U+2066–U+2069 and U+FEFF in retained text. Controls are not accepted as stored data. Plain text only; escape on render, never interpret HTML/links. |
| `phoneNumber` | Null stays null. Reject CR/LF/TAB and the prohibited controls/invisible characters above **before trim**, so multiple lines cannot become one accepted value. ECMAScript trim edges; collapse runs of U+0020 spaces to one; blank becomes null. Maximum 32 UTF-16 units after normalization. Nonempty value must contain at least one Unicode decimal digit. Allow Unicode letters/combining marks/decimal digits and U+0020 plus `+ - ( ) . # :` for organizational telephone and extension notation, including `ext`, `x`, `ต่อ`. Reject other characters; no slash/comma/semicolon list syntax. Single organizational value only; not a collection parser or personal/emergency phone. No strict E.164, dialability verification, numeric parsing, country inference or extension extraction. |

Examples allowed: `02-123-4567`, `(02) 123 4567`, `02-123-4567 ต่อ 123`, `+66 2 123 4567 ext 9`. These are formatting examples, not seeded contact values. Reject oversized text rather than truncate; validation errors name the field safely without echoing values. No email, website, opening hours, map URL, latitude/longitude, structured province/district/subdistrict, staff phone, emergency contact, multiple-phone collection or contact taxonomy.

## 7. Desired-state write and retry semantics

`expectedUpdatedAt: null` means **expect Contact row absence**, not “ignore version”. Existing-row expectation is its exact server-issued `updatedAt.toISOString()` token. Reject malformed/noncanonical timestamps; all new Contact timestamps stored at millisecond precision. No unguarded upsert, last-write-wins or automatic token replacement.

Order: persisted authorization → expected absence/version check → normalized equality/NOOP → guarded state change → atomic audit → commit. Check version **before** equality.

| Current / expectation / desired state | Result |
| --- | --- |
| Absent / null / both null | NOOP, no row/timestamp/audit |
| Absent / null / at least one value | Create unique Contact; CREATED |
| Absent / timestamp / any values | Conflict; never recreate from stale state |
| Existing / null / any values | Conflict, including same desired values or cleared row |
| Existing / matching token / identical normalized values | NOOP; current projection, no timestamp/audit change |
| Existing / matching token / changed values | Guarded update; UPDATED; clearing one or both writes nulls, keeps row |
| Existing / stale token / any values, including identical | Conflict; no overwrite, version bump or success audit |

Creation explicitly sets createdAt=updatedAt=server clock instant. Update uses `new Date(max(serverNowMs, current.updatedAtMs + 1))` with finite valid millisecond server clock and conditional updateMany where hospitalId + row ID + current updatedAt; exactly one affected row required. Unique constraint prevents duplicates independent of service. Two first saves: one creator, loser conflicts after absence recheck. Two changed submissions with the same version: at most one state-changing winner; other conflicts. Two matching identical fresh submissions may both NOOP since no version changed.

Browser retry keeps **the original expectation and desired values**. If first attempt rolled back, same request can still succeed; if it committed, retry fails version/absence expectation and cannot duplicate write/audit or overwrite newer state. UI reloads authorized current projection after conflict/unknown outcome. Equality on reread can establish that current state matches desired state, **not** that this request historically committed; no REPLAY success is claimed. Unknown network/commit outcome displays “ยังยืนยันผลการบันทึกไม่ได้” and asks reload/review before a new explicit save. Never silently retry with a newer token. No receipt table is needed: stable singleton, retained empty row, expected state and monotonic versions prevent repeated state changes. This deliberately chooses safe conflict/reconciliation instead of historical attempt recognition.

## 8. Authoritative transaction, locks and failures

Select short interactive **ReadCommitted** transaction with explicit row locks plus optimistic version predicate. Existing Weight Goal provides the owner-row serialization mechanism; Contact adds locks on the actual authority rows to prevent revocation between recheck and commit. No external I/O/UI work inside transaction. Ordinary reads need no durable read audit or mutation lock transaction.

Acquire locks in this Contact operation's consistent order, using parameterized Prisma.sql / explicit selected fields, never SELECT * or unsafe interpolated SQL:

1. Actor User row `FOR SHARE`, selecting id/status/personId; missing or inactive denies. Locks protect User lifecycle/binding through commit.
2. Exact actor HOSPITAL UserRole row `FOR SHARE`; missing denies. Lock the actual role row, not only its User, so role deletion cannot race past authorization.
3. Exact target Hospital row `FOR UPDATE`, selecting id/status. Missing/inactive denies safely. This persistent row serializes all Contact writes for the Hospital, including when Contact is absent; protects Hospital lifecycle through commit without modifying identity or Hospital.updatedAt.
4. Exact actor/target HospitalMembership row `FOR SHARE`; recheck OWNER/ACTIVE and exact foreign keys. Missing/ineligible denies. This blocks demotion, suspension or membership deletion through commit.
5. Re-read all authoritative predicates after lock acquisition and current Contact within transaction, then compare expectation. Guard existing Contact write with current version; create only after absence is proven while Hospital lock is held. Write Contact + recordAuditEvent using **same transaction client** and return only after commit.

An authority revocation already committed before the relevant lock is acquired is observed and denies; a revocation attempting to write a locked authority row waits until this authorized mutation ends. This gives an explicit ordering instead of an unprotected check/write gap. Hospital FOR UPDATE prevents two first creations/updates despite absent-row locking being impossible. Unique FK/version predicates are additional invariants. ReadCommitted post-wait queries see committed state; SERIALIZABLE is unnecessary for this bounded singleton with authority rows held and guarded writes. No table/advisory locks or changes to unrelated governance services are required.

Existing governance/workforce lock order may differ: do not claim system-wide deadlock elimination. Deadlocks abort one transaction safely. Retry only database-confirmed rolled-back deadlock/write-conflict failures (Prisma P2034 or verified PostgreSQL 40P01 mapping), maximum **3 total attempts**, exponential delays 25ms, 50ms with full jitter in [0, delay], outside transaction. Reuse original input/expectation; reacquire/revalidate every attempt. No retry of Forbidden/NotFound/Validation/stale Conflict, arbitrary unique/FK errors, audit validation/failure or ambiguous commit/network failures. Unexpected P2002 must be rolled back and mapped to safe conflict, not overwrite/upsert. Exhaustion returns sanitized conflict; unknown result returns unconfirmed/infrastructure outcome without success.

Audit failure rolls back Contact. Failed create leaves no row; failed update leaves prior values/version; no partial success. Post-commit UI revalidation failure must not undo or re-execute write: retain known committed result if available, otherwise reconcile as unconfirmed. Request size/abuse protection → authentication → parse/validation → authorization → business rules → atomic persistence → post-commit revalidation → sanitized response. Reuse existing transport abuse protections; no unrelated global configuration/framework change. Contact inputs must not enter URLs, analytics, exception dumps or logs.
