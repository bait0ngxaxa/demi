# UXH-C.4 — การแสดงตัวตนโรงพยาบาลและตัวเลือกตามเครือข่าย

## ข้อกำหนดและขอบเขต

- Starting HEAD: `460d68460cf735fef7bb20b14e953a9b00ae732f`
- ข้อกำหนดที่ยืนยัน: ซ่อนรหัสโรงพยาบาลจากหน้าจอผู้ใช้ และจัดกลุ่มตัวเลือกขอใช้งานโรงพยาบาลตามความสัมพันธ์แม่ข่าย–ลูกข่ายที่บันทึกไว้จริง
- รหัสโรงพยาบาลยังเป็นตัวระบุภายในสำหรับ Hospital Master, การจับคู่ข้อมูล, การผูกข้อมูลกับโรงพยาบาล, audit และ payload เดิมของ Server Action
- รายการ Hospital Master ในหน้าขอใช้งานยังเลือกเฉพาะ `PENDING_VERIFICATION`; สถานะของโรงพยาบาลแม่ข่ายไม่ถูกส่งไปหน้าสาธารณะ
- ไม่เปลี่ยน schema, API, Server Action schema, eligibility policy, authorization, persistence หรือความสัมพันธ์แม่ข่าย–ลูกข่าย

## การซ่อนรหัสในส่วนติดต่อ

ลบรหัสออกจากหัวข้อ คำอธิบาย ป้าย สถานะ ตัวเลือกโรงพยาบาล รายชื่อ และ accessible name รวมถึงชื่อไฟล์ดาวน์โหลดที่เคยมีรหัส ส่วนที่ยังคงมีรหัสเป็นข้อมูลภายใน เช่น hidden field `hospitalCode`, payload สำหรับการออกรายงาน, React key และ identity matching

คงคอลัมน์และ metadata ของไฟล์นำเข้าที่เป็นสัญญา workbook ซึ่งได้รับการยอมรับไว้แล้ว ห้ามเปลี่ยนเพื่อให้หน้าจอดูสอดคล้อง เพราะใช้ตรวจเวอร์ชันและผูกไฟล์กับ Hospital ที่ถูกต้อง

ตัวอย่างรูปแบบที่ปรับ:

| ก่อน | หลัง | เหตุผล |
| --- | --- | --- |
| ชื่อโรงพยาบาลต่อท้ายด้วยรหัส | แสดงชื่อโรงพยาบาล | รหัสเป็นตัวระบุภายใน ไม่ใช่ข้อมูลช่วยเลือกสำหรับผู้ใช้ |
| แสดงรหัสแม่ข่ายในข้อมูลลูกข่าย | แสดงชื่อแม่ข่ายและชื่อโรงพยาบาลที่เลือก | ให้บริบทจากความสัมพันธ์จริงโดยไม่เปิดเผยรหัส |
| รายชื่อตัวเลือกแบบแบน | แสดงเป็นกลุ่ม `เครือข่าย: [ชื่อแม่ข่าย]` | ช่วยให้เห็นความสัมพันธ์ตามข้อมูลที่บันทึก |

## กฎการจัดกลุ่มและการเลือก

- `listAvailableHospitalMaster` ยังคงกรองเฉพาะ Hospital ที่มีสถานะ `PENDING_VERIFICATION`; projection เพิ่มเพียง `id`, `name`, `parentHospitalId` และข้อมูล identity/name ของ parent ที่สัมพันธ์จริง
- จัดกลุ่ม direct child ด้วย parent ID ที่ตรงกัน และยอมรับเฉพาะ parent ระดับบนสุดตามกฎ hierarchy ปัจจุบัน เรียงชื่อด้วย locale ไทยและใช้ ID เป็นตัวเรียงเมื่อชื่อเท่ากัน
- ถ้า parent ไม่อยู่ในรายการที่เลือกได้ จะแสดงชื่อเป็นหัวข้อกลุ่มอย่างเดียว ไม่แสดงสถานะหรือรายละเอียด governance และไม่มีปุ่มเลือก parent
- ถ้า parent อยู่ในรายการที่เลือกได้ จะแสดงเป็นตัวเลือกแยกจากลูกข่าย การจัดกลุ่มไม่ให้สิทธิ์สืบทอดและไม่แก้ความสัมพันธ์ในระบบ
- รายการที่ไม่มี parent หรือความสัมพันธ์ไม่ครบ/ไม่ตรง/ซ้อนกัน จะไม่ถูกผูกเข้ากับกลุ่มที่คาดเดา แสดงในหัวข้อกลาง “โรงพยาบาลอื่น” โดยไม่แสดง diagnostic ภายใน
- เลือกด้วย Hospital ID เพื่อคง identity ที่ไม่ซ้ำกัน จากนั้นส่ง `hospitalCode` ของ record ที่เลือกจริงผ่าน hidden field เดิม ไม่ส่งรหัสของแม่ข่ายเมื่อเลือกลูกข่าย
- ค้นหาด้วยชื่อโรงพยาบาลหรือชื่อแม่ข่าย เมื่อชื่อแม่ข่ายตรงจะแสดงตัวเลือกของลูกข่ายในกลุ่มนั้น เมื่อชื่อลูกข่ายตรงจะคงหัวข้อแม่ข่ายไว้
- แยกข้อความ “ยังไม่มีโรงพยาบาลที่เปิดรับคำขอในขณะนี้” ออกจาก “ไม่พบโรงพยาบาลที่ตรงกับคำค้นหา”

## การเข้าถึงและความหมายที่คงไว้

ใช้ `<section>` ที่ตั้งชื่อจากหัวข้อ, รายการ `<ul>/<li>` และปุ่ม HTML ปกติ ไม่ใช้ ARIA listbox แบบไม่ครบ ปุ่มระบุโรงพยาบาลที่เลือกได้ มี focus style และใช้งานด้วยแป้นพิมพ์ได้ หลังเลือกจะย้าย focus ไปปุ่มเปลี่ยนโรงพยาบาล และเมื่อเปลี่ยนจะย้ายกลับไปช่องค้นหา สถานะประกาศชื่อโรงพยาบาลพร้อมบริบทแม่ข่าย

การจัดกลุ่มเป็นการนำเสนอเท่านั้น ผู้สมัครยังต้องส่งคำขอและรอการอนุมัติตาม flow เดิม การเห็นชื่อแม่ข่ายหรือการเลือก parent ที่มีสิทธิ์เลือกได้ไม่ได้ให้ authority แก่ parent ต่อลูกข่าย สอดคล้องกับ [ADR-0003](../adr/0003-hospital-led-onboarding.md) ที่ระบุว่า parent/main/sub เป็นข้อมูลประกอบ ไม่ใช่สิทธิ์ใช้งาน

## ประเด็นคงค้าง

- **OWNER DECISION REQUIRED:** หากมีโรงพยาบาลชื่อซ้ำภายในกลุ่มเดียวกัน (รวม “โรงพยาบาลอื่น”) ผู้ใช้ยังแยกตัวเลือกจากชื่อที่แสดงไม่ได้ ระบบคง identity และปุ่มของแต่ละรายการไว้แยกกัน แต่ไม่สร้างป้ายรหัสหรือคำอธิบายใหม่โดยไม่มีคำที่อนุมัติ
- ความสัมพันธ์ที่ขาดหรือไม่สอดคล้องจะแสดงในกลุ่ม “โรงพยาบาลอื่น” โดยไม่บอกสาเหตุทางเทคนิค ให้ UXH-D ยืนยันกับผู้ใช้ว่าการจัดกลุ่มแบบกลางนี้เข้าใจได้

## การตรวจสอบ

- Vitest เฉพาะ onboarding, projection, schema/action, hierarchy, mutation recovery และหน้า Admin hierarchy: **10 ไฟล์, 52 tests ผ่าน**
- `npm run typecheck`: **ผ่าน**
- ESLint แบบ scoped สำหรับไฟล์ TS/TSX ที่เปลี่ยนตั้งแต่ starting HEAD: **ผ่าน**
- `npm run lint -- --max-warnings=0`: **ไม่ผ่าน** เพราะ warning เดิม 2 รายการในไฟล์ภาพเนื้อหาโรงพยาบาลที่ไม่ได้เปลี่ยน (`hospital-content-image-list.tsx`, `hospital-content-image-manager.tsx`); ไม่มี error จากไฟล์ในงานนี้ และ repository ไม่มี script `lint:strict`
- Chrome บนหน้า onboarding จริง: ตรวจหน้า desktop 1536px และ mobile 390×844px; ค้นหาด้วยชื่อแม่ข่าย/ลูกข่าย และเลือกด้วย Enter โดยไม่ส่งฟอร์ม; ไม่พบ document overflow หรือปุ่มล้นแนวนอนใน mobile selector
- ไม่ได้ทดสอบด้วยโปรแกรมอ่านหน้าจอจริง และไม่ได้ส่งคำขอ onboarding จาก browser
- ไม่รัน build หรือ full test suite; ไม่มีการเปลี่ยน module boundary

## ส่งต่อ UXH-D

ทดสอบ UAT ด้วยบัญชีและ master data ที่อนุมัติแล้ว โดยเน้นชื่อซ้ำในแม่ข่ายเดียวกัน, orphan/ความสัมพันธ์ไม่สอดคล้อง, parent ที่ไม่ eligible แต่มีลูกข่าย eligible, การเลือก parent และ child แยกกัน, screen reader จริง และ viewport มือถือที่ใช้งานในโรงพยาบาล
