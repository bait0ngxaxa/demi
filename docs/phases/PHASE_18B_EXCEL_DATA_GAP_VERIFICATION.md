## 2. สถานะ readiness ที่ใช้

สถานะต่อไปนี้แยกกันได้และอาจเกิดพร้อมกันใน field เดียว:

| Status | ความหมายใน audit นี้ |
| --- | --- |
| SOURCE_MISSING | ไม่มี authoritative stored source สำหรับความหมายที่ลูกค้าต้องการ |
| SOURCE_EXISTS_NOT_PROJECTED | source อยู่ใน schema/service แต่ไม่อยู่ใน relevant Program/report projection |
| SOURCE_AVAILABLE_SEMANTICS_OPEN | มี field แต่ stage, scope, linkage, units, timing, meaning หรือ provenance ยังไม่ตรง/ไม่ยืนยัน |
| DERIVATION_UNAPPROVED | candidate inputs/logic มี แต่ formula, denominator, version, missing behavior หรือ validation ยังไม่รับรอง |
| AUTHORIZATION_OPEN | source อาจมี แต่ report/export actor, exact scope หรือ disclosure ยังไม่ได้รับอนุมัติ |
| PRESENTATION_OPEN | source/readiness อาจพร้อมบางส่วน แต่ output label, null/zero/withheld, order, layout หรือ compatibility ยังเปิด |
| VERIFIED_FACTUAL_SOURCE | ยืนยัน source และ ownership ใน code/schema ได้; ไม่ได้หมายถึง projection, semantics, clinical approval หรือ export authorization |

### 2.1 Actor/scope abbreviations ในตาราง

- **H-CARE**: authorized HOSPITAL user ที่เป็น direct active OWNER/MEMBER ของ Hospital/relationship scope; authority มาจาก server policy ไม่ใช่ client.
- **OSM-CARE**: OSM ที่มี exact active PatientOsmAssignment และ active OSM-Hospital relationship สำหรับ Hospital เดียวกัน; assignment ไม่แทน caregiver relationship.
- **SELF**: authenticated PATIENT ที่ server resolve เป็นเจ้าของ self PHR; personal wellness/medication/exercise scope.
- **H-COUNT**: exact Hospital count query ที่ผ่าน Hospital authorization predicate; ไม่ได้ทำให้ count นั้นเป็น authorized Excel cohort.
- PatientHospitalRelationship เป็น Hospital-local scope. Hospital parent/child ไม่สืบทอด clinical access; PatientProfile/Person join ห้ามลบขอบเขต Hospital/Program.

recordedBy, createdBy หรือ updatedBy บอกผู้ทำรายการตาม operation เท่านั้น ไม่ได้ยืนยันผู้ส่งมอบบริการหรือผู้รับผิดชอบดูแลตลอด Program.

## 8. Smallest set of blockers ต่อ reporting outcome

รายการต่อไปนี้เป็นกลุ่ม root cause ต่ำสุดที่ต้องปิดก่อนการ export จริง ไม่ใช่การสั่ง implement:

1. **Customer/clinical rule closure:** exact Hospital cohort/relationship eligibility, Program row grain, Before/During/After, classification, clinical units, score formulas, achievement denominator, outcome, plan-adjustment and obstacle semantics. (R24A-D01–D10)
2. **Capture/linkage gaps:** illness onset/duration, CVD source, After HbA1c/BMI-compatible inputs, achieved-day observation, structured follow-up outcome/adjustment/obstacle, service-delivery event, historical OSM attribution. (D05/D07/D09/D10)
3. **Existing source projection gap:** linked Baseline HbA1c/height/confidence, Screening PAM/PROM and personal exercise duration are not currently selected into relevant Program projection; the latter two also lack confirmed Program-stage relationship/meaning. (D06/D07)
4. **Export authorization/privacy:** no cohort/export capability, approved PII/clinical/OSM field allowlist, actor matrix, safe count policy, revocation/audit/delivery contract. Exact Program access cannot widen to cohort access. (RPT-24C)
5. **Snapshot/output readiness:** no coherent snapshot across both sheets, counts, pages and source lookups; no dataAsOf proof; six Follow-up slots need approved overflow behavior; missing/null/zero/withheld and ordering/template compatibility remain open. (D11–D15)

การแก้ projection อย่างเดียวไม่สร้าง source ที่ไม่มี. การเพิ่ม capture โดยไม่มี clinical/customer semantics ก็ยังไม่สร้าง field ที่มีความหมาย. การยืนยัน field ไม่ได้อนุญาต export.
