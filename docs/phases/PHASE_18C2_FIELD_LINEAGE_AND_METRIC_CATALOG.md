## 3. Source and time constraints

- Import template 28 columns A:AB มี Patient core, Initial Baseline, Classification และ OSM fields. Supported import persistence แคบกว่า template: Patient core, Baseline weight/height/waist/DTX/HbA1c, RISK/DIABETES และ OSM assignment ภายใต้ rules ปัจจุบัน. DOB/gender/contact/address/emergency contact ไม่ persist เพียงเพราะมี column.
- Import ไม่สร้าง PatientProgram. การเปิด Program เป็น operation แยกและอาจ link Baseline ผ่าน initialBaselineId ตามกฎปัจจุบัน; ห้ามนำ Baseline ไปใช้ทุก Program โดยอัตโนมัติ.
- PatientClassification RISK/DIABETES ไม่ใช่ DM/Pre-DM ที่อนุมัติ, ไม่ใช่ Program-stage snapshot และไม่ใช่จำนวน Program.
- คงความหมาย timestamp เดิม: recordedOn เป็น business date; createdAt เป็น persistence time; recordedAt เป็นเวลาบันทึกใน application; startedAt/completedAt เป็น Program lifecycle; assignment createdAt/endedAt เป็น assignment history. ไม่มี field ใดแทน service delivery/encounter date โดยอัตโนมัติ.
- Goal target ไม่ใช่ achievement; categorical Follow-up status ไม่ใช่ achieved days; COMPLETED ไม่ใช่ clinical success; Service 1 row ไม่พิสูจน์ delivery.
- Free-text และ attachment body/file ยังไม่มี allowlist. PersonalExerciseEntry เป็น Patient SELF wellness ไม่ใช่ Program clinical fact.

## 4. Proposed Metric Catalog

Keys ต่อไปนี้เป็น design identifiers ไม่ใช่ runtime permission หรือ approved KPI. Hospital และ Global ต้องใช้ definition/version เดียวกันเมื่อ population เทียบกันได้. Metric ถูก block จน source, population, grain, time, missing-value และ disclosure rules ได้รับอนุมัติ.

ก่อน implement ทุก key ต้องระบุ counting grain, eligible population/status, time range และ observation/as-of field, numerator/denominator เมื่อมี, duplicate/dedup treatment, missing-versus-zero/withheld behavior, definition version และ synthetic examples. ค่าที่แสดงในตารางเป็น source candidates; ช่องใดไม่ถูกกำหนดอย่างชัดเจนยัง pending และไม่มี metric ใดใน catalog นี้ได้รับการอนุมัติ.
