## 4. LINE ใน demo

ผู้ป่วยต้องเชื่อม LINE ก่อน โดยกดเมนูเชื่อมบัญชีใน Rich Menu ของ OA demo แล้ว login ด้วยบัญชีผู้ป่วย demo (ขั้นตอนตาม [PHASE_17J1_LINE_EXTERNAL_SETUP_RUNBOOK.md](../phases/PHASE_17J1_LINE_EXTERNAL_SETUP_RUNBOOK.md))

- **คำว่า “นัด” และ Quick Reply:** ผู้ป่วย A คนที่ 1–3 มีนัดภายใน 7 วันหลัง seed ส่งคำว่า “นัด” แล้วระบบจะตอบนัดถัดไป ส่ง “เมนู” หรือ “ช่วยเหลือ” เพื่อดู Quick Reply ตามบทบาท
- **เปิดการแจ้งเตือนนัดหมาย:** ใน Vercel `demi_demo` ให้ตั้ง `DEMI_LINE_APPOINTMENT_NOTIFICATIONS_GENERATION` เป็น UUID ใหม่ทุกครั้งที่เปิดรอบใหม่ (เช่น `node -e "console.log(crypto.randomUUID())"` ห้ามใช้ UUID ซ้ำกับรอบก่อนหรือกับ production) แล้วตั้ง `DEMI_LINE_APPOINTMENT_NOTIFICATIONS_ENABLED=true` และ redeploy ผู้ป่วยต้องเปิดรับการแจ้งเตือนนัดในหน้าตั้งค่าของตัวเองด้วย
- **เตือนกินยา:** ตั้ง `DEMI_LINE_MEDICATION_REMINDERS_DISABLED=false` ผู้ป่วยเปิดรับการเตือนยาในหน้าตั้งค่า แล้วแก้เวลาของยาหนึ่งรายการให้อยู่ภายในไม่กี่นาทีข้างหน้า (การเตือนจะส่งเฉพาะภายใน 15 นาทีหลังเวลาที่ตั้งไว้)
- **สั่ง scheduler tick เอง:** Vercel Hobby ไม่มี scheduler ให้ จึงต้องเรียก tick เองหลังสร้างหรือเลื่อนนัด หรือเมื่อถึงเวลายา

  ```bash
  curl -sS -H "Authorization: Bearer $DEMI_SCHEDULER_SECRET" https://<demo-host>/api/internal/scheduler/tick
  ```

  `DEMI_SCHEDULER_SECRET` ต้องตรงกับค่าใน Vercel (ยาวอย่างน้อย 32 ตัวอักษร) ผลลัพธ์เป็นจำนวนต่อขั้นตอนเท่านั้น และถ้ามี tick ที่สำเร็จไปภายใน 60 วินาทีก่อนหน้า ระบบจะข้าม (`TOO_SOON`)
- หลังสาธิต ให้ตั้ง `DEMI_LINE_APPOINTMENT_NOTIFICATIONS_ENABLED=false` และ `DEMI_LINE_MEDICATION_REMINDERS_DISABLED=true` กลับ

## 6. ตรวจ pipeline รายงานด้วยมือ

ทำตามขั้นตอนเดียวกับ test `tests/integration/report-pipeline-e2e.integration.test.ts` บนผู้ป่วยใหม่ที่ไม่ใช่ข้อมูล seed

1. OWNER รพ.สต. นำเข้าผู้ป่วยใหม่ด้วยไฟล์ Excel template v3 (ชื่อขึ้นต้นด้วย “ทดสอบ”) แล้วบันทึกประวัติสุขภาพพร้อมปีวินิจฉัย และมอบหมาย อสม.
2. บันทึกข้อมูลตั้งต้น (น้ำหนัก ส่วนสูง รอบเอว ความดัน DTX HbA1c CVD % ไม้บรรทัดวัดใจ) แล้วกด **เปิด Program**
3. อสม. ครั้งที่ 1: บันทึกสัญญาณชีพ ทำแบบประเมิน PAM/PROMs และบันทึกกราฟวัดลอยจม การ์ดความฝัน ตารางกิจวัตร และไม้บรรทัดวัดใจ
4. ครั้งที่ 2: บันทึกสัญญาณชีพ (มีส่วนสูง) แล้วทำแผนสุขภาพ (เช่น ลดข้าว/แป้ง 5 วัน และคาร์ดิโอ 3 วัน วันละ 30 นาที)
5. ครั้งที่ 3–6: บันทึกการติดตามผล 4 ครั้งพร้อมจำนวนวันที่ทำได้ ครั้งที่ 4 ตอบ “ปรับแผน” แล้วสร้างแผนฉบับปรับ
6. OWNER บันทึก Final Assessment (น้ำหนัก, HbA1c, CVD %) แล้วกดจบ Program
7. เพิ่มผู้ป่วยอีกหนึ่งคน และบันทึกแบบประเมินกับการติดตามผล **นอก Program** (ฟอร์มจะแจ้งว่ารายการนี้จะไม่อยู่ในรายงานตาม Program)
8. เปิดรายงานโรงพยาบาล ตัวเลขก่อนดาวน์โหลดต้องเพิ่มขึ้น 1 Program และเพิ่มผู้ป่วยที่ไม่มี Program 1 ราย จากนั้นส่งออก Excel แล้วตรวจว่า
   - ชีต “Dashboard ภาพรวม” แถวของผู้ป่วยรายแรกมีชื่อ, HN, ระยะเวลาป่วย (ปี), อสม., วันเริ่ม, Before ทุกช่อง, DTX/BW ครั้งที่ 1–6, % ความสำเร็จครั้งที่ 3–6, BMI และ After ทุกช่อง (ช่อง % ของครั้งที่ 1–2 แสดง “ยังไม่พร้อมใช้งาน: ยังไม่มีสูตรที่ได้รับรอง” ตามที่ออกแบบไว้)
   - ชีต “รายงานการจัดบริการ” มี PAM/PROMs, ไม้บรรทัดวัดใจ, เครื่องหมาย “ทำ” ของ Service 1, ช่องแผนครั้งที่ 2, วันที่ติดตาม วันที่ทำได้ % ความสำเร็จ และคำตอบปรับแผน/อุปสรรค
   - ผู้ป่วยรายที่สองไม่มีแถวในทั้งสองชีต แต่ถูกนับในหัวรายงาน (“ความสัมพันธ์ผู้ป่วยที่ยังไม่มี Program”)
